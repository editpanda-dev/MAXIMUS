# 장한별 키우기: 애착 인터랙션 토이 PRD

- 문서 상태: 사용자 검토 대기
- 작성일: 2026-08-21
- 대상 플랫폼: iPhone 세로형
- 다음 산출물: Figma 생성 프롬프트, iOS 구현 계획

## 1. 배경

「장한별 키우기」의 최종 경험은 화면 속 장한별들이 자유롭게 살아가고, 플레이어가 필요할 때 직접 집어 일시키고 쉬게 하는 캐주얼 방치형 육성 게임이다. 그러나 경제, 체력, 업무, 휴식, 부화를 모두 만들기 전에 가장 중요한 제품 가설을 먼저 검증해야 한다.

> 플레이어는 보상 때문이 아니라 장한별의 행동과 반응이 귀여워서 화면에 머물고 반복해서 만진다.

본 PRD는 이 가설만을 검증하는 1차 인터랙션 토이를 정의한다.

## 2. 목표

아무 설명과 보상이 없어도 사용자가 Long Press로 장한별 집기를 스스로 발견하고, 허우적거리는 모션과 놓는 방식에 따른 반응을 탐색하며 반복 상호작용하게 한다.

핵심 감정은 `웃기고 귀여움 80% + 살짝 귀찮아하는 반응 20%`다. 학대나 고통의 인상보다 장난치는 친밀감이 앞서야 한다.

## 3. 사용자와 테스트 상황

- 1차 테스트 대상: 지인 5명 내외
- 방식: 조작 설명 없이 iPhone을 건네고 첫 2분을 관찰
- 진행자 금지 사항: “길게 눌러봐” 등의 직·간접 힌트, 성공 반응 유도

## 4. 범위

### 4.1 포함

- iPhone 세로형 단일 HOME
- 장한별 1명
- 최소 IDLE 행동: 걷기, 멈추기, 주변 바라보기
- Tap 반응 2~3종
- Long Press, Drag, Drop
- 놓는 속도에 따른 안전 착지와 짧은 던지기
- 8프레임 허우적 모션
- 행동 시점별 햄틱과 작은 효과음
- 앱 중단·재개 시 안전 복귀
- Reduce Motion 대응

### 4.2 제외

- 장알별 부화
- 재화, 상점, 광고, 결제
- 체력, 업무, 휴식, 집중 근무
- 세이브, 방치 수익, 재접속 보상
- 장한별 추가 수집과 다중 캐릭터
- 호감도, 감정 누적, 대사, 음성
- 튜토리얼, 조작 문구, 손가락 힌트
- 강한 충돌, 부상, 고통, 장시간 쓰러짐 연출
- 재방문율, 경제 밸런스, 알 구매 의향 검증

## 5. 시각 방향

- 따뜻한 미색 배경의 빈 방
- 상시 UI, 소품, 이름표, 메뉴 없음
- 제공된 흑백 선화를 기준으로 함
- 그림자와 미세한 종이 질감만 허용
- 캐릭터 표정과 동세를 가리는 포인트 컬러 제외
- 캐릭터 터치 영역은 실제 선화 외곽보다 넓게 설정

## 6. 상태 모델

장한별은 `IDLE`, `REACTING`, `HELD`, `LANDING` 네 가지 상태만 가진다.

| 현재 상태 | 입력/이벤트 | 다음 상태 |
|---|---|---|
| IDLE | Tap | REACTING |
| IDLE | Long Press 성공 | HELD |
| REACTING | 반응 완료 | IDLE |
| REACTING | Long Press 성공 | HELD |
| HELD | 손가락 Release | LANDING |
| LANDING | 착지 반응 완료 | IDLE |
| LANDING | Long Press 성공 | HELD |

### 6.1 IDLE

- 걷기, 멈추기, 주변 바라보기 중 하나를 수행한다.
- 행동 사이에 짧은 무작위 간격을 두어 기계적인 반복을 피한다.
- Tap, Long Press 입력을 받는다.

### 6.2 REACTING

- Tap 시 0.4~0.8초 동안 고개 돌리기, 눈 맞추기, 움찔하기 중 하나를 재생한다.
- 재생 중 Tap은 무한 큐에 쌓지 않고 무시한다.
- 재생 중 Long Press가 성공하면 반응을 자연스럽게 끊고 HELD로 전환한다.
- 반응 완료 후 IDLE로 복귀한다.

### 6.3 HELD

- Long Press가 인식되면 자율 행동을 즉시 중단한다.
- Long Press 초깃값은 0.3~0.4초로 두고 실제 기기 테스트로 조정한다.
- 캐릭터를 1.05~1.1배 확대한다.
- 8프레임 허우적 루프를 재생한다.
- 드래그 속도에 따라 모션 재생 속도를 1.0~1.5배 사이에서 조정한다.
- 손가락을 즉시 따라붙기보다 아주 약간 늦게 따라와 말랑한 무게감을 만든다.
- 캐릭터 중심은 화면 안전 영역을 벗어나지 않는다.

### 6.4 LANDING

- 손을 놓을 때의 이동 속도로 안전 착지와 짧은 던지기를 구분한다.
- 천천히 놓으면 안정적으로 착지하고 IDLE로 돌아간다.
- 빠르게 놓으면 제한된 거리만 이동한 뒤 휘청이거나 짧게 데굴한다.
- 가장 강한 반응은 `짧은 데굴 → 몸 털기 → 0.5초 째려보기`로 제한한다.
- LANDING 중 Long Press는 현재 모션을 자연스럽게 끊고 HELD로 전환한다.
- LANDING 중 Tap 반응은 잠시 막는다.
- 모든 결과는 IDLE로 복귀한다.

## 7. 감각 피드백

| 시점 | 시각 | 햄틱 | 사운드 |
|---|---|---|---|
| HELD 진입 | 1.05~1.1배 확대, 허우적 시작 | 짧고 가벼운 피드백 | 작은 `톡` |
| HELD 유지 | 8프레임 루프 | 그 자체로 반복 햄틱은 사용하지 않음 | 필수 없음 |
| 안전 착지 | 부드럽게 닿고 IDLE 복귀 | 약한 피드백 | 부드러운 착지음 |
| 짧은 던지기 | 휘청/데굴/째려보기 | 중간 피드백 | 탄성 있는 착지음 |

- 음성 대사와 반복적인 신음은 제외한다.
- 사운드 또는 햄틱이 비활성화되어도 시각 반응만으로 상태를 이해할 수 있어야 한다.

## 8. Figma 전달 구조

Figma는 실제 물리 손맛을 검증하는 최종 프로토타입이 아니라 시각 상태와 모션을 iOS로 전달하는 명세서다.

- `00 Foundations`: 배경, 선 두께, 그림자, 캐릭터 기준 크기
- `01 Character Assets`: 기본 원화와 Tap 반응
- `02 Held Motion`: 8프레임 허우적 모션
- `03 Landing States`: 안전 착지, 휘청, 데굴, 째려보기
- `04 HOME Prototype`: iPhone 세로형 상태 전환 시연
- `05 iOS Handoff`: 재생 시간, easing, 햄틱, 효과음, export 이름

다음 단계의 Figma 생성 프롬프트는 위 페이지와 상태를 명시적으로 생성하고, `design-assets/reference` 원본을 참조하도록 작성한다.

## 9. iOS 개념 구조

Figma 승인 후 iOS는 SwiftUI 셸과 SpriteKit 인터랙션 공간을 결합한다.

- `SwiftUI App Shell`: 앱 실행과 SpriteKit 화면 표시
- `HomeScene`: 터치 판정, 캐릭터 위치, 바닥과 화면 경계
- `CharacterNode`: 장한별 시각 자산과 애니메이션
- `CharacterStateMachine`: 네 상태의 전환
- `MotionController`: 손가락 추적, 속도 계산, 짧은 던지기 상한
- `FeedbackController`: 햄틱과 효과음
- `IdleBehaviorController`: 자율 IDLE 행동 선택

입력과 결과의 흐름은 다음과 같다.

`Input → HomeScene → CharacterStateMachine → Motion/Animation → Feedback → IDLE`

상태, 시각 자산, 움직임, 피드백을 분리해 원화나 허우적 프레임을 바꿔도 물리 규칙에 영향을 주지 않도록 한다. 향후 다중 장한별로 확장할 때 각 캐릭터는 독립 상태 머신을 가진다.

## 10. 예외 처리

- 빈 곳 Tap: 아무 반응 없음
- Long Press 인식 전 손가락 이동: 캐릭터 상태 유지
- HELD 중 화면 밖 Drag: 캐릭터 중심을 안전 영역으로 제한
- 앱 백그라운드 이동: Drag 속도를 폐기하고 안전한 위치에서 IDLE 복귀
- Tap 연타: 반응을 무한히 쌓지 않음
- 프레임 드롭: 한 프레임의 최대 이동 거리를 제한
- 사운드·햄틱 미지원: 메시지 없이 생략
- Reduce Motion 활성화: 확대와 탄성을 줄이되 상태 변화는 유지

## 11. 검증

### 11.1 기능 검증

- Tap이 캐릭터 터치 영역에서만 반응한다.
- Long Press가 HELD로 일관되게 전환된다.
- Drag 중 캐릭터가 화면 밖으로 나가지 않는다.
- 놓는 속도에 따라 안전 착지와 짧은 던지기가 구분된다.
- 모든 착지 반응이 IDLE로 복귀한다.
- 앱 중단·재개 후 캐릭터가 유효한 상태와 위치에 있다.
- 햄틱과 사운드가 없어도 상호작용이 이해된다.

상태 전환과 속도 상한은 자동 테스트한다. 손맛, 애니메이션, 햄틱, 효과음은 실제 iPhone에서 수동 검증한다.

### 11.2 5인 관찰 테스트 통과 기준

- 5명 중 4명 이상이 60초 안에 Long Press를 스스로 발견한다.
- 5명 중 3명 이상이 첫 집기 후 자발적으로 3회 이상 다시 집는다.
- 5명 중 3명 이상이 놓는 속도나 방향을 바꿔 반응을 탐색한다.
- 웃음, 감탄, 캐릭터에게 말 걸기 등은 정성 신호로 기록한다.
- 2명 이상이 “무엇을 해야 할지 모르겠다”고 느끼면 발견성을 재설계한다.
