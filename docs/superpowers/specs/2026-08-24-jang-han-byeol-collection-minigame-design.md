# 장한별 키우기: 수집·성장·미니게임 설계

- 문서 상태: 사용자 승인 완료, 구현 계획 전 검토
- 작성일: 2026-08-24
- 대상: 모바일 우선 웹 프로토타입, 이후 iOS 이식
- 선행 문서: `2026-08-21-jang-han-byeol-web-prototype-design.md`

## 1. 제품 전환

기존 단일 HOME 인터랙션 토이는 장한별을 만지는 감정과 손맛을 검증했다. 이 버전은 그 감정을 유지하되, 반복 플레이가 수집과 성장으로 이어지는 게임 루프를 만든다.

핵심은 세 가지다.

1. HOME의 한별을 탭하거나 한별별 미니게임을 플레이해 계정 경험치와 돈을 번다.
2. 돈으로 랜덤 알을 구매하고, 부화한 한별을 컬렉션에 추가한다.
3. 같은 한별이 다시 나오면 자동 레벨업되어 그 한별의 돈 획득 효율이 오른다.

플레이어는 보유한 한별 중 하나를 HOME에 선택해 놓는다. 선택한 한별의 돈벌이 방식이 현재의 주 플레이가 된다.

## 2. 확정된 핵심 루프

```text
HOME에서 한별 선택
        ↓
선택 한별의 고유 플레이
        ↓
계정 XP + 별가루(돈) 획득
        ↓
별가루로 랜덤 알 구매
        ↓
새 한별 획득 또는 중복 한별 자동 레벨업
        ↓
더 높은 돈 보상으로 다시 플레이
```

- 계정 경험치는 캐릭터별로 분리하지 않는다.
- 계정 레벨은 이후 알 풀 확장, 추가 한별과 콘텐츠 해금의 기준이다.
- 한별의 레벨은 그 한별의 플레이 보상만 올린다. 높은 레벨 때문에 장애물, 타이밍 판정, 입력 난이도가 불리해지지 않는다.
- 진화는 현재 한별이 영구 변신하는 방식이 아니다. 알에서 얻은 한별을 수집하고 자유롭게 선택하는 방식이다.

## 3. 초기 한별과 돈벌이 방식

| 한별 | 초기 보유 | 조작 | 돈벌이 성격 |
| --- | --- | --- | --- |
| 기본 한별 | 시작 시 Lv.1 보유 | 순수 Tap | 즉각적·가벼운 연타 수익 |
| 스카이콩콩 한별 | 알에서 획득 | Tap 점프 | 생존·회피 실력 수익 |
| 튀김우동 한별 | 알에서 획득 | 타이밍 Tap | 주문 완성·콤보 수익 |

기본 한별 역시 알 풀에 포함한다. 시작 보유 상태여도 부화에서 다시 나오면 새 캐릭터가 추가되지 않고 즉시 기본 한별의 레벨이 오른다.

푸들 한별과 슬랑이와 노는 한별은 이후 알 풀에 추가할 확장 캐릭터다. 초기 구현의 게임 규칙과 저장 형식은 새 한별을 추가해도 바뀌지 않아야 한다.

## 4. 계정, 재화, 알

### 4.1 계정 경험치

- 모든 정상 플레이 결과는 계정 경험치를 지급한다.
- 기본 한별은 탭마다, 미니게임 한별은 세션 결과에서 경험치를 준다.
- 계정 레벨은 알 풀에 새 한별을 넣을 수 있는 잠금 조건에 사용한다.
- 초기 세 캐릭터는 계정 레벨 제한 없이 첫 알 풀에서 획득 가능하다.

### 4.2 별가루

`별가루`는 UI에 표시할 돈의 임시 이름이다. 제품 카피에서 다른 명칭으로 바꿀 수 있으나, 첫 구현에는 단일 재화만 사용한다.

- 기본 한별의 Tap과 두 미니게임의 정산이 별가루를 지급한다.
- 별가루는 알 구매에만 사용한다.
- 방치 수익, 재접속 수익, 광고 보상, 유료 재화, 교환소는 첫 버전 범위에서 제외한다.

### 4.3 알 구매와 부화

- 알 1개 가격의 초기 밸런스 값은 `100 별가루`다.
- 첫 알 풀은 기본, 스카이콩콩, 튀김우동 한별 세 종이다.
- 각 한별은 같은 확률(각 `1/3`)로 나온다.
- 구매 시 별가루를 차감하고 한 번의 확정 결과를 즉시 부화 화면에 표시한다.
- 새 한별이면 컬렉션에 `Lv.1`로 추가한다.
- 중복이면 해당 한별 레벨을 자동으로 `+1` 올리고, 중복 재료나 별도 확인 버튼은 만들지 않는다.

### 4.4 한별 레벨

- 초기 최고 레벨은 `Lv.10`이다.
- 레벨 보상 계수의 초기값은 `1 + 0.10 × (레벨 - 1)`이다. 즉 Lv.10은 해당 한별의 별가루 보상이 1.9배다.
- 최고 레벨 캐릭터가 중복으로 나올 때의 보상은 초기 버전에서 `별가루 환급`으로 처리한다. 환급값은 밸런스 데이터로 둔다.
- 가격, 확률, 최고 레벨, 보상 계수는 코드 로직이 아니라 밸런스 데이터에서 읽는다.

## 5. 기본 한별: 순수 Tap 수익

기본 한별은 HOME에서 플레이하는 가장 짧고 단순한 수익 방식이다. 길게 누르기, 드래그, 자동 생산, 타이머는 사용하지 않는다.

### 5.1 규칙

- HOME에 기본 한별을 선택하면 캐릭터를 탭할 수 있다.
- 유효한 탭마다 계정 경험치와 별가루를 지급한다.
- 연속 탭은 짧은 콤보를 만들며, 콤보 보너스는 별가루에만 적용한다.
- 정해진 유휴 시간 후 콤보는 0으로 돌아간다.
- 각 탭은 짧은 표정·스케일·별가루 튀김 반응을 낸다. 반응은 입력을 막지 않는다.
- 기본 한별의 레벨은 탭당 별가루와 콤보 보너스만 높인다. 계정 경험치량은 캐릭터 레벨과 무관하다.

### 5.2 초기 밸런스 항목

| 항목 | 초기 값 | 비고 |
| --- | ---: | --- |
| 유효 Tap당 XP | 1 | 계정 공통 |
| 유효 Tap당 별가루 | 1 | 레벨 계수 적용 전 |
| 콤보 유효 시간 | 1.8초 | 마지막 Tap부터 계산 |
| 콤보 단계 | 10회 단위 | 보너스 수치는 데이터화 |

숫자는 첫 플레이 테스트 후 조정한다. 구현은 클릭 빈도에 비례해 렌더링 작업이 무한히 쌓이지 않도록, 보상 이벤트와 시각 효과를 분리한다.

## 6. 스카이콩콩 한별: 새우·마늘 회피 런너

### 6.1 플레이 감정

구글 공룡게임처럼 단순한 한 버튼 생존 게임이다. 스카이콩콩을 탄 한별이 화면 왼쪽의 바닥선을 달리고, 새우와 마늘이 오른쪽에서 다가온다. 귀여운 점프 타이밍으로 오래 버티는 것이 목표다.

### 6.2 세션 규칙

- 한 판은 충돌 전까지 계속되는 횡스크롤 세션이다.
- 바닥에 있는 상태에서 Tap하면 점프한다. 공중 Tap은 추가 점프를 만들지 않는다.
- 새우와 마늘은 장애물이며, 오른쪽에서 왼쪽으로 이동한다.
- 스폰 간격과 속도는 시드 기반 규칙으로 생성해 테스트 시 재현 가능하게 한다.
- 회피 성공과 생존 거리로 점수를 쌓는다.
- 한별과 장애물이 충돌하면 즉시 종료하고 결과 화면으로 전환한다.
- 결과에서 거리, 회피 수, 획득 XP와 별가루를 보여준다.

### 6.3 보상

```text
별가루 = (기본 생존 보상 + 거리 보상 + 회피 보상) × 한별 레벨 계수
XP = 거리 보상 + 회피 보상
```

- 레벨 계수는 별가루에만 적용한다.
- 장애물 속도와 충돌 판정은 레벨과 무관하다.
- 수익 계산은 게임 화면이 아닌 공통 보상 서비스가 수행한다.

## 7. 튀김우동 한별: 주문 완성 타이밍 게임

### 7.1 플레이 감정

튀김우동 한별은 한 그릇을 정확하고 빠르게 완성하는 리듬형 Tap 게임이다. 스카이콩콩의 생존·회피와 달리, 정해진 순간을 맞추고 연속 성공해 주문을 완성하는 만족감을 준다.

### 7.2 세션 규칙

- 한 판은 `45초`다.
- 주문마다 면, 국물, 튀김, 고명 등의 재료 순서가 있다.
- 현재 재료가 타이밍 링의 판정 영역에 들어오면 Tap한다.
- 판정은 `Perfect`, `Good`, `Miss` 세 단계다.
- Perfect와 Good은 주문 진행과 콤보를 올린다. Miss는 현재 주문의 완성도와 콤보를 낮추지만 세션을 즉시 끝내지 않는다.
- 모든 재료를 성공적으로 넣으면 한 그릇이 완성되고 다음 주문이 시작된다.
- 45초 종료 시 완성 그릇 수, 완성도, 최고 콤보, XP, 별가루를 정산한다.

### 7.3 보상

```text
별가루 = (그릇 완성 보상 + Perfect 보너스 + 콤보 보너스) × 한별 레벨 계수
XP = 그릇 완성 보상 + 판정 보상
```

- 한별 레벨은 별가루 보상만 높인다.
- 판정 창, 재료 속도, 주문 길이는 레벨과 무관하다.
- 난이도 상승은 캐릭터 레벨이 아닌 별도 스테이지 또는 계정 레벨 해금으로 나중에 추가한다.

## 8. 화면 흐름

```text
앱 시작
  ↓
HOME (선택한 한별, 계정 XP, 별가루)
  ├─ 기본 한별 선택 → HOME Tap 수익
  ├─ 스카이콩콩 선택 → 게임 시작 → 결과 → HOME
  ├─ 튀김우동 선택 → 게임 시작 → 결과 → HOME
  ├─ 컬렉션 → 보유 한별 선택
  └─ 알 상점 → 별가루 차감 → 부화 결과 → 컬렉션/HOME
```

첫 버전의 HOME은 캐릭터의 감정적 중심이다. 상단에는 필요한 최소 정보(계정 레벨·XP 진행·별가루), 하단에는 컬렉션과 알 상점 진입을 둔다. 선택된 한별의 게임 시작 방법은 캐릭터와 가까운 위치에서 명확하게 제공한다.

## 9. 구현 경계

웹 프로토타입은 TypeScript 도메인 로직과 PixiJS 화면을 분리한다. 이 경계를 지키면 이후 iOS에서는 SwiftUI/SpriteKit 화면만 교체하고 게임 규칙을 대응시킬 수 있다.

```text
Pixi/DOM 입력
   ↓
Screen Coordinator
   ↓
AccountProgress + CollectionService + EggService
   ↓                         ↓
MiniGameSession (Pogo / Udon / BaseTap) → RewardResult
   ↓
RewardService
   ↓
Versioned LocalSave
```

### 9.1 도메인 모델

- `AccountProgress`: 계정 XP, 계정 레벨, 별가루, 선택 한별 ID
- `HanbyeolRosterEntry`: 한별 ID, 보유 여부, 레벨
- `CharacterDefinition`: 이름, 자산 경로, 해금 조건, 미니게임 ID
- `EggPoolDefinition`: 후보 ID, 가중치, 해금 조건, 가격
- `BalanceConfig`: 가격, 확률, 레벨 보상, 판정·점수·보상 계수
- `MiniGameSession`: 순수 상태 머신과 시간 단위 업데이트를 가진 플레이 세션
- `RewardResult`: 세션 결과의 원시 점수와 지급 후보
- `RewardService`: 보상 계산과 계정 반영을 담당하는 단일 경로

### 9.2 미니게임 인터페이스

모든 미니게임은 화면 코드와 독립적으로 다음 생명주기를 따른다.

```text
create(seed, playerLevel) → receive(input) → tick(deltaSeconds) → snapshot()
    → isComplete() → finish() : RewardResult
```

- `PogoSession`은 점프·중력·장애물·충돌을 소유한다.
- `UdonSession`은 주문·재료·타이밍 판정·콤보를 소유한다.
- `BaseTapSession`은 Tap·콤보 만료·탭 보상을 소유한다.
- PixiJS는 snapshot을 렌더링하고 입력을 session 이벤트로 변환할 뿐, 점수나 재화를 직접 수정하지 않는다.

### 9.3 저장

- 첫 버전은 브라우저 로컬 저장만 사용한다.
- 저장 데이터에는 버전 번호를 포함한다.
- 저장 시점은 보상 확정, 알 부화 확정, 한별 선택 변경 시점이다.
- 저장 데이터가 없거나 손상되면 안전한 초깃값(기본 한별 Lv.1, 별가루 0, XP 0)으로 시작한다.
- 서버 계정, 동기화, 오프라인 방치 수익은 범위 밖이다.

## 10. iOS 이식 원칙

| 웹 | iOS 대응 |
| --- | --- |
| `AccountProgress`, `CollectionService`, `RewardService` | Swift 순수 모델/서비스 |
| `PogoSession`, `UdonSession`, `BaseTapSession` | SpriteKit에 독립적인 Swift 세션 모델 |
| Pixi Scene/View | `SKScene`/`SKNode` 또는 SwiftUI 뷰 |
| Browser Pointer Event | `UITouch`/SwiftUI tap gesture |
| LocalStorage adapter | `UserDefaults` 또는 파일 저장 어댑터 |

규칙과 밸런스는 프레임 수가 아닌 초 단위 `deltaTime`과 데이터 모델로 표현한다. 충돌과 타이밍 판정은 렌더링 프레임률에 의존하지 않는다.

## 11. 테스트 기준

### 11.1 도메인 자동 테스트

- 유효 Tap, 콤보 만료, 기본 한별의 XP·별가루 계산
- 알 구매 시 잔액 차감, 난수 시드에 따른 일관된 결과
- 새 한별 획득과 중복 자동 레벨업
- Lv.10 도달 뒤 중복의 환급 처리
- 레벨 계수가 XP나 미니게임 난이도를 바꾸지 않음
- 스카이콩콩 점프, 장애물 이동, 충돌, 보상 결과
- 튀김우동 Perfect/Good/Miss, 주문 완성, 콤보, 45초 종료 결과
- 모든 보상은 `RewardService` 단일 경로로만 계정에 반영됨
- 저장 직렬화, 복원, 손상 데이터 초기화

### 11.2 브라우저 수동 검증

- 모바일과 데스크톱에서 빠른 Tap이 스크롤·선택과 충돌하지 않는다.
- 스카이콩콩의 점프와 충돌이 화면 크기·프레임률에 관계없이 일관된다.
- 튀김우동의 타이밍 판정이 한 번의 Tap에 한 번만 적용된다.
- 게임 종료 후 HOME으로 돌아와 보상·선택 한별·컬렉션이 즉시 갱신된다.
- 새로고침 후 계정·알 결과·캐릭터 레벨이 복원된다.

## 12. 초기 범위와 후속 범위

### 포함

- 기본·스카이콩콩·튀김우동 한별 3종
- 계정 XP, 별가루, 랜덤 알, 중복 자동 레벨업
- HOME 선택, 세 개의 고유 수익 방식
- 로컬 저장, 결과 화면, 최소 컬렉션·상점

### 제외

- 푸들·슬랑이 한별의 플레이 방식
- 희귀도, 복수 알 종류, 천장, 조각, 교환, 뽑기 연출 고도화
- 방치 수익, 친구/랭킹, 계정 로그인, 클라우드 저장
- 광고, 결제, 분석 SDK
- 신규 원화 제작과 최종 UI 아트 디렉션

## 13. 완료 조건

- 세 한별은 HOME에서 선택 가능하고, 각자 서로 다른 방식으로 별가루를 만든다.
- 별가루로 알을 사고, 결과가 컬렉션과 중복 레벨업에 정확히 반영된다.
- 모든 플레이 보상은 계정 XP와 별가루의 공통 정산 경로를 통과한다.
- 캐릭터 레벨이 보상만 올리고 미니게임 난이도를 바꾸지 않는다.
- 새 한별과 미니게임을 기존 저장·경제 코드 변경 없이 추가할 수 있다.
- 웹 도메인 규칙을 iOS의 Swift 모델로 옮길 수 있도록 브라우저·Pixi 코드와 분리한다.
